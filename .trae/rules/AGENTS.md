# AGENTS.md · 项目文档固定规则

本文件为项目级永久规则（工作区规则目录 `.trae/rules` 自动加载）。所有「写文档 / 更新 README」任务必须遵守，优先级高于个人写作习惯。

## 一、README 方案固定

1. README 一律采用【根 README + backend/README + frontend/README】三份方案，**不合并为单文件，也不拆成两个仓库文档**。
2. 目录映射（以实际工程为准，不重命名目录）：
   - 根文档：`README.md`
   - 后端文档：`admin_system_backend/README.md`（文档中称 backend）
   - 前端文档：`meeting-vue/README.md`（文档中称 frontend）
3. 职责边界：
   - **公共内容只放根 README**：项目介绍、功能特性、整体技术栈、快速启动、项目亮点、工程结构、文档导航。
   - **backend 只写后端专属**：Nacos（注册发现 / 配置中心 / 降级）、数据库连接与脚本、表结构、Knife4j / OpenAPI、分布式锁、MQ 与 Outbox、定时任务。
   - **frontend 只写前端专属**：Node 版本、启动与打包、开发代理、环境变量、构建部署注意事项。
4. 子文档不得复制根文档的公共段落，只允许用一行链接引用根文档。

## 二、写文档任务禁止事项

1. 写文档任务**只输出 Markdown 文本**，严禁修改、新增、删除、重构以下内容：
   - Java 源码、Vue / JS 源码、前端组件与样式
   - 接口定义、请求参数、返回结构、状态枚举
   - `application.yml` 等任何配置文件
   - SQL 脚本、表结构、索引、种子数据
2. 文档任务不得顺带「修 bug」「优化代码」「调整配置」；确有需要时另开任务并先获得确认。
3. 文档任务不触发 Builder 阶段流转，不更新 `ROADMAP.md` / `STATE.md` / `CHECKLIST.md` 的阶段状态。
4. 不创建多余文档：不新增 README 副本、临时说明、重复指南；不把同一内容写到多个文件。

## 三、内容真实性要求

1. 文档必须与代码、配置、SQL 实际一致；涉及版本号、端口、路径、类名、表名、字段、配置项时，先读代码或脚本确认。
2. 禁止虚构接口、字段、配置项、环境变量和未实现的功能；未实现的能力标注「未使用 / 可选 / 预留」。
3. 版本号以 `pom.xml`、`package.json` 为准；表结构以 `docs/schema.sql` 为准；配置以 `application.yml` 为准。
4. 命令必须可直接执行，路径必须真实存在；链接使用仓库内相对路径。

## 四、写作规范

1. 统一中文、Markdown 格式；标题层级清晰，一个一级标题，二级标题按文档职责划分。
2. 表格优先用于版本、配置、表结构、对照关系；代码块必须标注语言。
3. 公共信息（账号、端口、接口前缀、统一响应体）只在根 README 定义一次，子文档引用而不重复。
4. 修改 README 前先读取当前内容，保留仍然正确的信息，删除与代码不符的旧描述。

## 五、执行顺序

1. 明确任务范围（仅文档）。
2. 读取相关代码 / 配置 / SQL 核对事实。
3. 按「根 → backend → frontend」顺序更新，先公共后专属。
4. 自检：链接有效、无重复公共内容、无代码改动（`git status` 仅出现 md 文件）。
